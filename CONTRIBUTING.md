# Contributing to fR3k

Thanks for taking an interest in this public code drop. Contributions are welcome, but please keep them focused, reproducible, and honest about their limits.

## Before you contribute

- Keep changes bounded to one clear improvement; use a focused issue or pull request.
- Preserve relevant licensing, attribution, and provenance when reusing code, data, prompts, or other material.
- Do not commit passwords, API keys, tokens, private telemetry, private host/device/location data, or copied material from private FR3K research or control-plane repositories.
- Treat measured facts, reproduced results, proposals, and guesses as different things. Say which one you are reporting.

## Pull requests

Please describe what changed, why it changed, and how another person can reproduce or test it. Include the relevant command output, fixture, configuration, version, commit, or measurement evidence for the code you touched. If a test cannot run, is flaky, or fails for a known reason, say so plainly rather than hiding it.

Small documentation fixes, reproducibility improvements, bug reports, and practical experiments are all useful. A contribution may be declined when its scope, provenance, privacy, or evidence cannot be established safely.

## Scope and expectations

This repository is an experimental open-source code drop, not a promise of production support or a guarantee that every component works on every system. Contributors are responsible for checking dependencies, permissions, external services, and hardware-specific assumptions in their own environment.

By submitting a contribution, you agree that it may be reviewed, modified, or declined under the repository's license and the practical safety, privacy, and evidence constraints above.
