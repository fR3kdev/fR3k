## Failure → correction → retest

Initial integration execution returned 5 FAIL out of 8 because the QEMU output matcher incorrectly compared escaped newlines and 32-bit ARM QEMU needed a larger virtual address-space reservation. Both defects were corrected on the feature branch; a dedicated regression assertion was added. Final 8/8 suite PASS came from **new** run IDs, not edited old evidence. Failed original receipts remain intact locally.

## Truth boundaries & remaining blockers

- Only userspace execution under host Linux was exercised on five foreign architectures; no foreign OS kernel boot is claimed.
- Windows, full Android emulators, BSD/OpenWrt guests, macOS/iOS, firmware peripheral simulation and real-device speech/accessibility validation are **not yet verified**.
- No QEMU full-system kernel boot, APK installation, browser automation or hardware-in-loop evidence exists in this run.
- Standalone SHA-256 record checks detect edits but are not independent cryptographic attestation; signed append-only off-host storage remains future work.
- Foreign Ubuntu package SHA-256 executable pins are locally fixed; end-to-end verification against signed Ubuntu arm64/armhf/ppc64el/riscv64/s390x package-index metadata remains outstanding.
- An unrelated privileged diagnostic was held for **operator approval** by the fleet gateway. It was not bypassed. The rootless testing work did not require it.
- Do **not** use the generic infrastructure-smoke PASS count as a release decision. Actual release-artifact fixtures and required-platform gates must be implemented before certifying a release.
